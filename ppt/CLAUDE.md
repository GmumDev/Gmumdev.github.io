# PPT 작업 규칙

이 폴더(`ppt/`)의 파일을 읽거나 수정할 때 항상 적용되는 규칙이다.

## 파일 구조

| 파일 | 역할 | 쓰기 |
|---|---|---|
| `portfolio_template.pptx` | 모든 포트폴리오의 기본 틀 (레이아웃·서체·색·슬라이드 구성의 기준) | **금지 (read-only)** |
| `portfolio_all.pptx` | 모든 개별 프로젝트 포트폴리오를 그대로 합친 통합본 | 가능 |
| `<project>_portfolio.pptx` | 프로젝트별 개별 포트폴리오 (예: `simple_rpg_portfolio.pptx`) | 가능 |
| `pptxAssets/` | pptx에 들어가는 모든 이미지/영상/gif의 유일한 보관처 | 가능 |
| `CODE_THEME.md` | 코드 블록 구문 강조 색상 규칙 (팔레트·판별 순서·낱말 목록) | 가능 |
| `tools/highlight_code.py` | 위 규칙의 구현. 코드 박스에 색을 다시 입히는 스크립트 | 가능 |

**산출물은 `portfolio_all.pptx`와 개별 프로젝트 pptx다.** 사용자의 지시에 따라 이 파일들을 다듬어 나간다.

## 슬라이드 구성

프로젝트 섹션은 3종류의 슬라이드로 구성한다:

1. **개요** — 프로젝트가 무엇인지, 한눈에
2. **상세** — 무엇을 어떻게 만들었는지
3. **구현** — 기술적으로 어떻게 풀었는지

새 프로젝트를 추가하거나 기존 섹션을 고칠 때 이 3분할과 `portfolio_template.pptx`의 레이아웃을 그대로 따른다. 템플릿에 없는 레이아웃을 새로 만들지 않는다.

## 규칙

### 1. 수정 범위
- **`portfolio_template.pptx`는 절대 수정하지 않는다.** 읽기 전용 참조 대상이다.
- **`ppt/` 폴더 바깥의 모든 파일은 read-only로 취급한다.** (`media/`, `assets/`, `portfolio/`, `index.html` 등) 읽어서 참고하는 것은 자유지만 쓰지 않는다.
- 쓰기가 허용되는 건 `ppt/` 안의 `portfolio_template.pptx`를 제외한 파일뿐이다.

### 2. 에셋
- pptx에 들어가는 **모든** 이미지·영상·gif는 **`ppt/pptxAssets/`에서만** 가져온다.
- 다른 위치의 에셋을 pptx에 직접 참조하거나 삽입하지 않는다.
- 필요한 소재가 바깥에 있으면(예: `media/smplrpg.mp4`) **원본을 건드리지 말고**, 필요한 형태로 가공한 사본을 `pptxAssets/`에 저장한 뒤 그것을 사용한다. (예: 영상에서 gif 추출, 해상도 축소, 포스터 프레임 추출)
- `pptxAssets/` 파일명은 용도를 알 수 있게 짓는다: `<project>_<용도>.<ext>` (예: `simple_rpg_gameplay.gif`, `dungeon_ui_overview.png`)

### 3. 동기화 — 사용자의 명시적 지시가 유일한 트리거
- 개별 프로젝트 pptx가 원본(source of truth)이고 `portfolio_all.pptx`는 파생물이다. 통합본만 먼저 고치는 방향은 하지 않는다.
- **`portfolio_all.pptx`는 사용자가 갱신하라고 지시할 때만 건드린다.** ("통합본 갱신", "portfolio_all 업데이트" 등)
- 그 외에는 통합본에 대해 **아무것도 하지 않는다.** 자동 갱신하지 않고, 뒤처졌는지 확인하지도 않고, 뒤처졌다고 알리지도 않는다. 수정시각 비교도 하지 않는다. 통합본 동기화 여부는 전적으로 사용자가 관리한다.
- 갱신 지시를 받으면 모든 개별 프로젝트 pptx의 현재 내용을 통합본에 반영하고, 어느 프로젝트를 어떻게 반영했는지 보고한다.

### 4. 파일 잠금 (Windows)
- 편집 대상 pptx가 PowerPoint에서 열려 있으면 저장이 실패한다. 작업 전 `~$*.pptx` 잠금 파일이 있는지 확인하고, 있으면 사용자에게 해당 파일을 닫아달라고 요청한 뒤 진행한다.

### 5. 코드 블록
- `IMPLEMENTATION` 슬라이드의 코드는 **추측해서 쓰지 않는다.** 해당 프로젝트의 실제 레포에서
  찾아 인용하고, 첫 줄에 `// <경로/파일명>` 주석으로 출처를 남긴다.
  줄을 생략할 때는 `...` 또는 `// ...` 로 표시하고, 원문에 없는 줄은 넣지 않는다.
- 레포 위치는 `KYO_GitRepos/` 아래에 있다 (Simple RPG → `personal-project-april-GmumDev`,
  Wielder → `NWJulyProject`, Winter Stove → `BunkerBliss`, Yummy Drawer → `PhysicsPuzzleSolver`).
  DungeonGame 은 로컬에 없고 `github.com/GmumDev/ConsoleDungeonGameSourceCode` 에 있다.
- 코드 문자열을 바꾼 뒤에는 **반드시 구문 강조를 다시 입힌다.** 문단을 새로 쓰면 색이 날아간다.

  ```bash
  python ppt/tools/highlight_code.py            # 전체
  python ppt/tools/highlight_code.py ppt/<project>_portfolio.pptx
  ```

- 색상 규칙은 **[CODE_THEME.md](CODE_THEME.md)** 에 있다. 색을 직접 지정하지 말고 이 문서와
  스크립트를 따른다. 팔레트를 바꾸려면 문서를 먼저 고치고 스크립트를 맞춘다.
- 코드 박스는 **15줄, 한 줄 68자(한글 2자)** 를 넘기지 않는다.

### 6. 다이어그램
- 캔버스 좌표 1 = 슬라이드 **0.72pt** 다. DETAIL 슬롯은 588×425, IMPLEMENTATION 슬롯은 518×342로
  그린다(각각 5.88×4.25in, 5.18×3.42in). **이미지 크기는 바꾸지 않는다.**
- 글꼴 크기는 아래 아래로 내려가지 않는다. 12 미만은 쓰지 않는다.

  | 용도 | 캔버스 | 실제 |
  |---|---|---|
  | 다이어그램 제목 | 18 | 13.0pt |
  | 결론 한 줄 | 16 | 11.5pt |
  | 노드 제목 | 15 | 10.8pt |
  | 본문 · 불릿 | 13.5 | 9.7pt |
  | 부연 · 캡션 | 12 | 8.6pt |

- **다이어그램은 구조만 보여준다.** 산문은 슬라이드의 설명 상자(`Text 4` · `Text 9` · `Text 10`)가
  맡는다. 다이어그램 맨 아래 결론은 한 줄 + 짧은 부연 한 줄까지다.
  글자를 키우려면 내용을 줄인다 — 이미지를 키우지 않는다.
- 색은 덱 팔레트를 따른다: 배경 `F4F4F4`, 테두리 `DEDEDE`, 강조 `2F6B5F`(배경 `E6EFEC`),
  본문 `1A1A1A`, 보조 `6E6E6E`, 경고 `B06048`(배경 `FAEFEB`).

### 7. 작업 방식
- pptx 조작은 `anthropic-skills:pptx` 스킬을 사용한다.
- 덮어쓰기 전에 대상 슬라이드의 현재 내용을 먼저 읽고 확인한다.
- 사용자가 지시하지 않은 슬라이드는 건드리지 않는다. 서식·문구를 임의로 "개선"하지 않는다.
- 작업 후에는 무엇을 어느 파일의 몇 번째 슬라이드에 바꿨는지 짧게 보고한다.
